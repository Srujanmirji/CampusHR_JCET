Units and status

Baseline sizes are logical iOS points, Android dp for layout and sp for text. 48 is the shared minimum target; 14 is the minimum metadata size. Body 17, secondary 15, navigation 18, section 20, greeting 26, large title 32. Space 4/8/12/16/20/24/32/40/48. Radius 8 controls,10 buttons,12 fields,14 appropriate cards,24 sheet top. No elevation by default.

Pending uses clock + label, approved uses check + label, rejected uses close + label, unavailable uses explanatory text with disabled control. Domain accent is not status: a violet leave icon does not mean approved. The supplied mint/amber/coral accents are not normal text colors: use their darker ink roles.

CampusHR V2 interaction specification

Frozen product behavior, 23 October 2026. No new screens, policies or actions. Timing below is a CampusHR tuning target, not a claim that Apple or Google prescribes these exact numbers. No separate SwiftUI reference file was provided: this specification applies the microinteraction principles in the brief. Final spring and haptic feel requires device calibration.

Shared rules

Acknowledge a touch within one display frame where possible, budget <100 ms. Never delay a network request to finish motion. Keep the original action label during loading, add a busy indicator, prevent duplicate writes. Only confirmed server results may produce a success label, success symbol, haptic or notification-delivered claim. Preserve inputs and context on failure. Announce status once through the platform accessibility API; do not repeatedly announce progress.

Respect the OS Reduce Motion setting before any in-app preference. Reduced motion uses immediate state updates or a <=100 ms crossfade, without translation, bounce, symbol morphing or shimmer. Haptics obey device and user settings independently; visual and spoken feedback always remain sufficient. No background animation. No motion on ordinary read-only metrics.

Springs and interruption

Use the platform system spring for sheets, swipe cancellation, picker and navigation. For a custom selection indicator only, an initial tuning target is response 0.25 s, damping fraction 0.9 with zero intentional overshoot; Android equivalent is a highly damped spring. These are not cross-platform physics guarantees. Stop or retarget in-flight selection motion on new input. Never queue haptics. No authored spring on chart values, list entrance, or routine data refresh.

Platform implementation

iOS: NavigationStack, TabView, sheet with detents appropriate to content, native confirmationDialog/alert, swipeActions, refreshable, Picker and DatePicker. Image(systemName:) for symbols; SF Symbol effects only for a meaningful changed state and availability-gated. UISelectionFeedbackGenerator for committed selection; UIImpactFeedbackGenerator medium for committed actions. Accessibility Reduce Motion controls authored motion; do not override the native system's adaptation.

Android: NavigationBar and NavigationBarItem, ModalBottomSheet, AlertDialog, DatePickerDialog, exposed semantics for all actions, and platform back handling. Use Material state layers, never a second custom ripple. HapticFeedback constants chosen for semantic action and device capability; Android should not mechanically mimic iPhone amplitudes. Cancel predictive-back returns the user to the same draft and scroll position.

Data and failure boundaries

  • Lost response after submission: display “Checking your request…” and reconcile with the server before allowing a retry that could duplicate the write. Do not claim the operation failed or succeeded without evidence.
  • Assignment conflict: stay at confirmation, explain that availability changed, return to refreshed recommendations. No success haptic.
  • Expired session: preserve nonsensitive draft fields as appropriate, ask to sign in; do not cache passwords or attachments.
  • Notifications permission denied or delivery pending: assignment may succeed independently. Say “Assignment saved” and “Notification pending” unless delivery evidence supports “Notification sent”.
  • Recommendation match percentages are supplied sample values, not a client-computed or approved scoring algorithm. Explain subject fit, capacity and availability; do not add points or rankings.

References: Apple motion, Apple sheets, Android accessibility, Material navigation. Platform behavior is native; CampusHR timing is a tuning proposal.

Platform adaptations and developer handoff

Product design V2 is frozen for development. These are separate iOS and Android review packages; browser previews communicate visual treatment and content, not working native widgets. The original faculty package remains unchanged. All sample identities, leave requests, metrics, matches, notifications and assignment results are synthetic.

iOS package

Twelve exported views: Login, Home, Timetable (Today with Week access), Attendance, Leave, Apply Leave, Notifications, Profile, HOD Approvals, Leave Review, Smart Coverage, Settings.

Use system SF Pro, with V2's named hierarchy as the baseline. Map titles to largeTitle/title2/headline, body to body, secondary to subheadline and caption to a readable footnote. Use scaled metrics for custom sizes; no maximum Dynamic Type cap or minimumScaleFactor to squeeze labels. The browser uses the Apple system font on macOS as a specimen, not proof of Dynamic Type support.

Use NavigationStack for push destinations and TabView for root destinations. Preserve independent tab stacks; native leading back button and edge-swipe return to the previous view. Hide bottom tabs for the full-screen Apply Leave flow. Root tabs remain Faculty Home/Timetable/Attendance/Leave/Profile; HOD Home/Approvals/Timetable/Workload/Profile. Bell is top-right, Settings is inside Profile. Do not add Notifications as an HOD root tab.

SF Symbols are the only product glyph family. Specimen PNGs are exported using AppKit system symbols on this Mac; native iOS implementation uses Image(systemName:) with OS availability fallbacks. Do not ship raster exports or assume macOS availability proves the oldest supported iOS version. See ICONS.md.

Use native segmented Picker, DatePicker, sheet, alert and contextMenu. Password Help uses a content-sized sheet with safe-area-aware bottom action. Apply Leave remains a full-screen form; do not put a long form into a cramped half sheet. Confirm rejection with reason; context menus may expose existing actions, never silently commit decisions. Swipe actions have accessible button equivalents.

SafeAreaInset for sticky decision actions; scroll content gets matching bottom padding. Respect the home indicator, navigation bar and keyboard insets, including landscape. Keyboard Next moves through form fields; Done dismisses where appropriate. Scroll invalid field into view and keep its real label and error visible. On cancel/back with edits, show native discard confirmation and preserve the draft if cancelled. iPad uses bounded readable content, not stretched phone rows.

Android package

Same twelve content destinations and role permissions. Inter remains the frozen V2 body/display family with system sp scaling. Do not force fontScale=1 or cap scaling; reflow rows and action groups when space is insufficient.

Use Material 3 Scaffold with a NavigationBar, selected icon indicator and Material state layers. Top app bar uses Android's back arrow; Android back first dismisses the keyboard, then sheet/dialog, then the current pushed destination. At a root destination follow platform app-exit expectations; do not cycle tabs as a fake history. Support predictive back through the navigation framework. Gesture and three-button navigation insets must both work.

Use Material Symbols Outlined consistently. Selected state is indicated by the container and label, never color alone. Browser font is the same licensed Google symbol subset used by the frozen faculty specimen. Do not mix SF exports into Android.

Use Material DatePickerDialog, ModalBottomSheet and AlertDialog. Native Material text fields own focus/error/supporting-text states; the specimen's tinted field is visual intent only. V2 color roles map to primary/action, onPrimary/onAction, surface/surface, surfaceContainer/surfaceSecondary, onSurface/ink, onSurfaceVariant/textSecondary, outline/controlStroke, error/coralInk. Success mintInk and warning amberInk remain explicit product roles. Component shape remains restrained by V2 instead of applying giant rounded containers everywhere.

Dynamic color may affect neutral app-adjacent surfaces only after every text pair is validated. Keep action blue, leave violet, attendance mint, warning amber, destructive coral and the small JCET orange accent stable. Brand assets and semantic status roles never change with wallpaper. No dynamic color implementation or new dark palette is part of this design freeze.

Keep all targets >=48 dp, even if a visual icon is 24 dp. Use WindowInsets.safeDrawing and IME padding; no buttons behind keyboard or system navigation. At large text, allow stacked action rows and vertically expanded navigation labels instead of ellipsis for critical meaning.

Backend truth and capability boundaries

The requested “Approve & Find Cover” label is retained as a design fixture with an explicit “HOD recommendation · Final approval is still required” qualifier. Production must use “Recommend approval” for a nonfinal HOD actor, show the actual approval chain, and only enter assignment after final approval permits it. This is a capability binding, not a permission change. Reject follows server authority as well. The prototype never unlocks final approval when its HOD action is tapped; Smart Coverage is a separate already-approved fixture.

Revalidate assignment availability and workload on commit. Never compute match scores in the client, or infer that 94% is a validated recommendation model. Workload thresholds, attendance percentages and academic-continuity definitions come from the backend and institutional policy. No new metric formula is approved here.

Institutional SSO, location attestation, lunch tracking, support addresses and full profile subfeatures are design entry points, not claims of implemented integrations. Do not make fake API data appear live. Use confirmed API capabilities and explicit unavailable states until integrations exist. Confirmed notification delivery is separate from assignment creation.

Inconsistencies identified and resolved in new artifacts

  • HOD approval segments now use three columns; workload summary inherits no unrelated faculty flex layout.
  • New HOD Review and Assign controls initially lacked the shared button base. Added the existing button primitive, restoring the 48 minimum and the same disabled/focus semantics.
  • HOD stub destination buttons initially inherited browser button borders. Removed those borders in the HOD specimen so root navigation follows V2.
  • A direct translation of the supplied approval CTA would misrepresent current HOD authority. Added a visible final-approval qualifier and separated the approved coverage fixture; the production role binding is mandatory in PLATFORMS.md.
  • Visual review caught a relative URL that prevented SF masks from loading; corrected the asset base and added HTTP-failure assertions to the check.
  • SF Symbols and Material Symbols cannot share a renderer on iOS. Added separate system-symbol review exports and a native-image handoff requirement; Android uses only Material.
  • The provided institutional logo asset is a JGI mark, not a verified official JCET crest. Preserve it as supplied for continuity; obtain approved institutional artwork before release. Do not fabricate a crest.

The requested Faculty screens were not changed to fix these new-preview issues. No new features, metric formula, role permission or dark palette is introduced.

State acceptance for every data screen

Initial load: stable title/navigation with matching static skeleton. Populated: current server data and period. Empty: successful zero result with contextual message. Recoverable error: retry the failed read, keep useful cached context. Offline: explicitly stale read-only context and preserved draft. Permission loss: explain unavailability and remove unauthorized action. Write pending: block duplicate commit. Write failure: preserve input. Uncertain outcome: reconcile before retry. Success: confirmed response only. Screen-specific variants are listed in SCREENS.md; none can be omitted merely because the happy-path PDF is complete.

Remaining native acceptance before release

Run actual iOS and Android builds on the smallest supported phones and a large device; test landscape, 200% and accessibility text sizes, long identities, native date picker, keyboard Next/Done, interactive sheet dismissal, predictive/edge back, safe areas, gesture/three-button navigation, VoiceOver/TalkBack order and announcements, assistive alternative to swipe, reduced motion, disabled haptics, slow/offline reconnect, expired session, assignment conflict and lost write response. Confirm SF availability on the minimum iOS version and check real fonts after fallback. These are acceptance gates, not passed results.
